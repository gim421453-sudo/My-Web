작성일: 2026-07-21

## 보정 내용

- Google 전용 Firebase 계정은 삭제/민감 작업 시 비밀번호 입력 모달을 열지 않고 Google `reauthenticateWithPopup`으로 바로 이동한다.
- 이메일/비밀번호 Firebase 계정은 `EmailAuthProvider.credential` + `reauthenticateWithCredential`이 성공해야 작업을 실행한다.
- Firebase 계정이 아닌 로컬/레거시 계정은 기존 로컬 비밀번호 확인 경로를 유지했다.
- 방과후/동아리/특강 메인 사이드탭을 직접 누르면 상세 화면 락을 해제한다.
- 방과후/동아리/특강 상세 화면에서 저장 직후에는 짧은 시간 동안 같은 상세 화면을 유지한다.
- 삭제로 비워진 프로그램 목록은 사용자가 다시 등록하기 전까지 기본 강좌를 자동 재생성하지 않는다.
- 시간표 교시는 `periodTimesConfiguredV81`이 true이면 저장된 `periodTimes`만 사용한다.
- 홈페이지 관리 저장 버튼은 렌더링 마지막 단계에서 현재 `saveSiteSettingsV2`로 다시 연결한다.

## V99 시간표 P1 보정

작성일: 2026-07-21

범위: 3단계 1차 인증 통합 이후 재현된 시간표 P1 버그만 보정했다. 신규 AuthProvider 범위, 기존 로그인 구조, Firestore Rules, Firestore 스키마, 실제 사용자/workspace 데이터는 변경하지 않았다.

| 항목 | 원인 | 수정 파일 |
|---|---|---|
| 시간표 로딩 누락 | 시간표 렌더 중 `store.timetableSets`가 비어 있으면 기본 시간표를 자동 생성하고 저장할 수 있어 Firestore 실시간 반영 순서와 충돌했다. | `app.js` |
| 빠른보기 불일치 | 빠른보기가 `store.timetable`에 행이 없을 때 레거시 빠른보기 배열로 fallback하여 전체 시간표와 다른 데이터를 보여줄 수 있었다. | `app.js` |
| 개별 교시 삭제 미반영 | `periodTimes` 행에 안정적인 문서 ID가 없고 삭제 시 원격 삭제 표시가 남지 않아 Firestore snapshot에서 삭제한 교시가 되살아날 수 있었다. | `app.js` |
| 교시 시간 전체 삭제 미반영 | 전체 삭제도 개별 삭제와 동일하게 기존 원격 `periodTimes` 문서를 삭제 대상으로 표시하지 못했다. | `app.js` |
| 시간표 이름 변경 실패 | 이름 수정 버튼이 누적 렌더/패치 흐름에서 오래된 active set 값을 사용할 수 있고, 프로그램 시간표 이름은 프로그램명과 따로 저장될 수 있었다. | `app.js` |

| 버튼 혼선 | `시간표 일괄 삭제` 패널은 수업 배정 초기화/교시 초기화 기능과 중복되어 사용 범위가 불명확했다. | `app.js` |

## V99 보정 내용

- 렌더 중 기본 시간표 자동 생성/저장을 막고, 기존 행이 있는데 세트 문서만 없을 때는 화면 표시용 세트만 복구한다.
- 빠른보기, 전체 시간표, 방과후/동아리/특강 상세 시간표가 모두 `store.timetable`을 기준으로 읽는다.
- `periodTimes`에 `period-1` 같은 안정적인 ID를 부여하고 삭제 시 `markWorkspaceDeleted("periodTimes", id)`를 호출한다.
- 개별 교시 삭제와 교시 시간 전체 삭제는 최종 확인 후 재인증이 성공해야 저장된다.
- 시간표 이름 변경은 현재 선택값을 다시 읽고, 프로그램 시간표는 프로그램명까지 함께 갱신한다.
- 기존 `현재 시간표 삭제` 버튼을 복구했다.
- `시간표 일괄 삭제` 패널은 `선택 시간표 비우기`, `현재 시간표 삭제`, `교시 시간 전체 삭제`와 중복되어 숨겼다.

## V99 브라우저 확인 필요

- 사용자는 임시 시간표/임시 교시로 개별 삭제, 교시 시간 전체 삭제, 현재 시간표 삭제를 확인해야 한다.

## V100 보정 내용

- 빠른보기 기준 시간표를 `pm-timetable-set` 현재 선택값으로 통일했다.
- 빠른보기 선택박스 변경 시 `pm-timetable-set`과 `quickTimetableSet`을 함께 갱신한다.
- legacy schedule 또는 오래된 빠른보기 배열 fallback을 사용하지 않고 `store.timetable`만 읽는다.
- 선택 요일에 행이 없지만 현재 시간표에 행이 있으면 빈 상태 대신 현재 시간표 전체를 표시한다.
- 시간표 저장/렌더 후 빠른보기 팝업이 열려 있으면 자동으로 다시 그린다.
